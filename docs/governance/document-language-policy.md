# Documentation Language Policy

- Status: Adopted from the owner's explicit instruction on 2026-09-07.
- Scope: Project-wide documents and documentation in component repositories.

## Review and canonical documents

1. Prepare documents for owner review in Japanese. Explanations, tables, and
   diagram labels should be understandable in Japanese; retain technical names,
   identifiers, commands, and code where translation would change their meaning.
2. After approval, write or update the canonical document in English. Preserve
   the approved meaning, scope, decisions, and acceptance criteria.
3. Apply the same process to substantive revisions: review the proposed changes
   in Japanese, then reflect approved changes in the English canonical document.
4. Clearly identify Japanese review drafts as drafts. If retained after adoption,
   link them to the English canonical document and label them as review history
   or a non-canonical translation; do not maintain two competing authorities.

Translation of approved content does not itself require another approval round.
If translation reveals a substantive ambiguity or requires a design change,
resolve that specific issue with the owner in Japanese before adopting it.

## Existing documents

This policy does not trigger a bulk translation of existing documents or alter
historical evidence. Apply it when preparing a review or adopting or revising a
canonical document. An unapproved Japanese proposal remains a review draft.
