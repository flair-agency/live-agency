# 外貨売上移行のProvider・監視引継ぎ準備

2026-09-08。承認済みの2Skill分割に対する、ローカル調査の記録。
新しい会計方針やProvider名を採用する提案ではない。

## 確認結果

売上計上・入金消込の候補は独立した計画作成入口を持ち、共通計算を
`foreign-revenue-core` に置いている。両方とも公開を防ぐprivate候補であり、
外部取得・会計登録・監視操作は実装していない。2Skill分割の再承認は不要。

現在のProviders・共有packages・Runtimeのmanifest 15件を調べた。
仕訳、売掛金、確定請求書、為替情報を提供すると宣言するBindingはなかった。
既存のMoney Forward Cloud Expense Providerが宣言するのは経費候補の取得と
経費登録であり、会計の複合仕訳や取込銀行明細の消込に転用できる証拠はない。
この調査は全インストール済みコネクターの機能不存在を証明するものではない。

## 残る能力と受入条件

| 担当範囲 | 必要な成果 | 受入で確認する条件 |
| --- | --- | --- |
| 請求書の取得・正規化 | 確定請求書、原本hash、請求番号・売上月・通貨・金額・発行日の一意な正規化 | 選択したsource profileと原本が一致。暫定値・曖昧な原本を計画に通さない |
| 為替と営業日 | 適用済み方針に合う公表レートと日付、出典と検証証拠 | 月末／直前公表営業日の判定と、採用したレートの対応を再現可能にする |
| 会計の読取り | 同一請求書・原本hash・月の既存登録、未消込売掛金、取込銀行候補の完全な検索 | 0件・1件・複数件、既消込、検索範囲不完全を区別。absenceだけで未登録と推測しない |
| 宛先への束縛 | 選択した会計主体、組織、期間、科目・取引先・税区分・銀行元の安定ID | 意味上の計画と別の実行束縛を対応付け、変更があれば停止。足りないマスターを自動作成しない |
| 売上計上の登録・照合 | 承認された日付・摘要・借方貸方を持つ仕訳と読戻し結果 | 直前の再計画hashが一致。応答不明時の重複登録を防ぐ |
| 入金消込の登録・照合 | 為替差損益を含む仕訳と、元の取込銀行明細への紐付け | 仕訳だけでなく明細状態・リンクも一致。単独仕訳で代替しない |
| Runtimeの監視引継ぎ | 既存監視IDと未決済・承認待ち状態を保つ移行記録 | 同じ請求単位の重複監視を作らず、書込み承認を監視設定から推測しない |

計画入力の `source_verified`、`policy_date_verified`、各match/countは
Providerから渡す正規化値であり、その値自体が取得・完全性を証明するわけではない。
受入では、それぞれに新しい実読取りの証拠を対応させる必要がある。

## 現行監視の保持

ローカルのautomation設定を対象文字列で絞り込み、元の
`foreign-revenue-accounting` を参照するACTIVEなheartbeatを1件確認した。
この設定は新しい2候補を参照していない。内容・ID・スケジュールを変更せず、
照合用hashを私的記録に保存した。請求番号、対象口座、金額、監視IDやpromptは
本書やGitHubへ転載しない。

この確認はローカルの該当設定1件の保持確認であり、別ホストや別サービスを含む
全監視の棚卸しではない。実際の切替時には、対象請求単位・現在の監視ID・未決済
状態・承認待ち計画・選択先Runtimeを改めて束縛する。旧監視を名前検索で削除したり、
計画の成功だけで新監視を作成したりしない。
