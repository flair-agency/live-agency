# 招待可否の書込接続：実装レビュー

[PR #79](https://github.com/flair-agency/live-agency/pull/79) の設計採用を受けた実装です。採用済みの責務・検証保証は[英語の正式契約](../architecture/record-dataset-write-contract.md)にまとめました。この文書は実装のレビュー資料で、本番登録の完了報告ではありません。

## 変更内容

| 所有者 | 実装する責務 |
| --- | --- |
| Lark Base Provider | 論理フィールドを設定済みの列・型へ変換し、既存writerで日時更新・新規作成・画像追加を実行。対象IDの完全行読戻しと型を考慮した比較で検証する。 |
| Invitation Skill | 既存の分類・履歴計画を再確認し、書込準備・承認済み計画の実行・中断後の読取照合を提供する。状態マスターの表示名とリンク先IDを使い分ける。 |
| Runtime | 既存のBinding解決と `authorizeIntent` / `onEvent` 接続を利用する。具体的なLark処理の追加は不要。 |
| 親リポジトリー | 正式契約・実装証跡を保存し、実際のRuntimeを使った接続検証と呼出箇所の検出を更新する。 |

新経路の書込準備・登録後検証・画像所属確認では、履歴テーブル全件のID列挙を行いません。既存のProfile経路はそのまま残します。新規IDの保証変更は、PR #79で承認された範囲です。

## 検証

ProviderとSkillの検証では、画像付き新規登録と日時更新、実際のリンク型への変換、同内容の再照合、設定・画像・既存行の変更、応答IDの不正、途中失敗を扱っています。取得できていない画像を省略して成功扱いにはしません。

親の接続検証は、既存の開発用依存と選択したソースを一時ディレクトリーにコピーし、実際のRuntime・Provider・Skillを実行します。置き換えるのは外部サービスの応答だけです。日時更新1件、対象行限定の読戻し、関係のない列・行の保持、承認・イベント保存接続、読取専用の再照合、設定変更時の停止を確認します。

独立した呼出箇所検出には `getRecords` / `getRecord` を追加しました。新しい読取方法を使う呼出元が検出対象から漏れないことと、API操作の定義を検証しています。

接続検証スクリプトのSHA-256は `f88696aeaf250268365cc95850d1f00720cc9d54ecd9266c57850d50ea43a658` です。既存の開発用依存を利用し、依存の追加インストールは行っていません。API応答は合成データなので、本番での画像取得・書込の成功や実行時間を証明するものではありません。

PR #27では、応答が返らない要求も残り時間で停止するよう修正しました。送信済み要求を取消す機能は現Transportにないため、書込の期限切れは結果不明として保持します。遅延した応答から後続処理を始めず、元の記録を照合します。この修正後にも実Runtimeとの接続検証は成功しました。

## 中断時に引き継ぐもの

元の業務計画、書込準備結果、承認対象のハッシュと件数、画像原本、永続ジャーナルを保持します。実行claimと対象データのロックは、選択した環境ファイルに結び付いた場所で保持します。ログ名を変えて排他を避けることはできません。失敗時のロックは読取専用の照合が確認済み・不足となるまで残し、矛盾・不明なら解除しません。

不明な作成や画像追加を再送せず、不足と確認できた分だけ新しい計画と承認で処理します。画像付きチェックポイントの自動再開は追加していません。

## 残る作業と判断

1. 実装PRのソースレビューと採用。
2. 固定版の配布、本番の明示的な構成変更・復旧案の準備と承認。
3. 現在のデータから登録計画を作り直し、実際の登録件数・変更内容・画像を提示して承認を得た後に本番検証。

本番環境はChatGPT Workの「C|OPS|エージェンシー運営」です。ローカルの接続検証を本番受け入れとして扱いません。[移行 #14](https://github.com/flair-agency/live-agency/issues/14) は、本番での業務完了と必要な引継ぎ確認まで閉じません。
